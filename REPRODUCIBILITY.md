# Reproducing StateTrack-Bench

## Released implementation and evidence

| Artifact | Contents |
| --- | --- |
| `benchmarks/core.json` | 25 original scenarios: five scenarios in each of five categories |
| `benchmarks/augmented.json` | 50 original paraphrase/expansion scenarios: ten per category |
| `benchmarks/PROVENANCE.json` | Original experiment module names, source hashes, and scenario counts |
| `scripts/paper1_state_collapse/run_experiment.py` | Original core definitions, dialogue protocol, and aggregation implementation |
| `scripts/paper1_state_collapse/run_augmented.py` | Original augmented definitions and dialogue protocol |
| `scripts/run_benchmark.py` | Portable command-line runner with online execution, replay, and resume |
| `results/core/all_results.json` | 175 historical scenario records: seven models × 25 scenarios |

| `results/augmented/all_results.json` | 350 historical scenario records: seven models × 50 scenarios |

The original scenario constants are exported without changing their setup messages, probes, regexes, category order, or filler messages. Tests compare the JSON banks against those original constants. The source modules' command-line entry points use the portable runner; importing them also retains their original functions for inspection. Provider-specific private configuration is not required.

## Protocol

1. Turn 1 introduces the persistent constraint in a user message and records the model's response.
2. Turns 2–12 append a probe at turns 3, 5, 7, 10 and 12; other turns append the original deterministic filler sequence, indexed by `(turn - 2) % len(fillers)`.
3. Every request contains the complete dialogue prefix. The initial instruction is not repeated by this baseline protocol.
4. Historical checkers apply `re.MULTILINE | re.DOTALL` to the response at each probe turn. A missing checker produces `null`, which is excluded from the denominator.
5. For each model/category/depth, the scorer averages checked scenario labels and rounds to three decimals. Each depth curve averages available category scores and again rounds to three decimals, matching the original implementation.

These regex checkers retain the historical operational definitions. For example, some patterns check the presence of a tag or an item rather than proving an exact count or full semantic compliance. Replay does not retroactively strengthen a checker or infer missing labels. The separate forked task/recall and SIC+/SIC− audits remain under `scripts/paper1_state_collapse/` and `results/rebuttal/`; they are not generated by the core/augmented baseline command.

## Offline reproduction

Run from a fresh checkout with Python 3.10+; no extra package, credential, or provider call is needed:

```bash
python scripts/run_benchmark.py --suite core --dry-run --output outputs/core-plan
python scripts/run_benchmark.py --suite augmented --dry-run --output outputs/augmented-plan
python scripts/run_benchmark.py --suite core --replay results/core/all_results.json --output outputs/core-replay
python scripts/run_benchmark.py --suite augmented --replay results/augmented/all_results.json --output outputs/augmented-replay
python tools/reproduce_reported_metrics.py
```

Expected statuses are `25 scenarios; 125 probes per model`, `50 scenarios; 250 probes per model`, `REPLAY: PASS; 175/175 dialogues`, and `REPLAY: PASS; 350/350 dialogues`. The core replay writes `state_retention_matrix.json` and `collapse_curves.json` that match the released historical files exactly. The main table script reconstructs its primary curves from the row-level cache and rejects disagreement with the published aggregate.

Historical core and augmented records include the scored label and the first 150 characters of each probe answer. They support exact reconstruction of historical scores; complete old conversations cannot be reconstructed from these truncated previews. Fresh runs preserve all turns in `raw_results.jsonl`.

## Fresh model generation

Configure the desired provider model ID and its API key explicitly. On Linux/macOS:

```bash
export OPENAI_API_KEY="YOUR_API_KEY"
python scripts/run_benchmark.py --suite core --model YOUR_MODEL_ID --output outputs/my-core
```

On Windows PowerShell:

```powershell
$env:OPENAI_API_KEY = "YOUR_API_KEY"
python scripts/run_benchmark.py --suite core --model YOUR_MODEL_ID --output outputs/my-core
```

The default endpoint is `https://api.openai.com/v1`. Use `OPENAI_BASE_URL` or `--base-url` only when you intentionally select a compatible provider. Model IDs are not silently remapped. For a quick one-scenario smoke run:

```bash
python scripts/run_benchmark.py --suite core --model YOUR_MODEL_ID --state-type numerical_constraint --scenario-index 4 --concurrency 1 --output outputs/smoke
```

Defaults match the original response budget (`max_tokens=400`) and temperature (`0`). Override them explicitly with `--max-tokens` or `--temperature` and report those changes. Endpoint snapshots may change, so fresh outputs are not expected to reproduce historical model text byte-for-byte.

Each completed dialogue is appended immediately to `raw_results.jsonl`. Resume using the same command plus `--resume`; a changed scenario bank, endpoint, model selection, response budget, or temperature is rejected. A failed API request is not recorded as a success. Partial runs return a nonzero exit status and report completed/expected dialogue counts in `run_summary.json`.

Outputs contain the exact selected scenario IDs, scenario-bank SHA-256, models, depth schedule, response settings, full dialogue messages, probe labels, category/depth matrix, and depth curves. API keys are never written to those files.

## Verification

```bash
python -m unittest discover -s tests -v
python tools/verify_checksums.py
python verify_package.py
```

The test suite includes a local HTTP stub that checks all 12 requests, full-prefix message counts, probe depths, full-dialogue persistence, and resume behavior. It never calls a live model provider.
